\begin{abstract}
Les grands modèles de langage subissent une date de coupure des connaissances ; intégrer des informations postérieures sans ré-entraînement complet motive des stratégies variées : récupération augmentée (RAG), adaptation efficace des poids (LoRA), pseudo-RAG à l'entraînement (RAFT), affinement du retrieveur par \emph{reranking}, ou encore décision de recherche via \emph{function calling}.
Nous comparons six configurations sur un socle centré \emph{LLaMA 3.1 8B} : \textbf{baseline} (Groq, sans contexte), \textbf{RAG} (FAISS + chunks 400 mots, Groq), \textbf{fine-tuning LoRA} supervisé (Unsloth, adaptateur \texttt{lora\_adapter\_ft}), \textbf{RAFT} (contexte gold + distracteurs FAISS au train, adaptateur \texttt{lora\_adapter\_raft}), \textbf{RAG + reranking} (cross-encoder multilingue puis Groq), et \textbf{function calling} (outil \texttt{search\_docs} + Groq).
Le jeu de données (Option~B) est entièrement en français, généré via l'API Groq (\texttt{llama-3.1-8b-instant}), \textbf{même famille} que la baseline et le RAG : le biais circulaire doit être discuté explicitement.
Les agrégations de métriques (EM, F1, BERTScore, ROUGE-L, proxy d'hallucination, latence, etc.) sont produites par le notebook~\texttt{08\_evaluation.ipynb} à partir des six fichiers \texttt{*\_predictions.json}.
Les lignes du tableau principal correspondant à RAFT, au reranking et au function calling doivent être \textbf{recopiées} depuis \texttt{final\_report.json} après chaque campagne complète ; les valeurs historiques ci-dessous illustrent surtout baseline, RAG et fine-tuné.
\end{abstract}

\subsection{Fine-tuning LoRA}
% Unsloth, QLoRA 4-bit, format Alpaca ; notebook 04 ; adaptateur lora_adapter_ft.
Le fine-tuning (notebook~\texttt{04\_finetuning.ipynb}) entraîne un adaptateur LoRA (\texttt{lora\_adapter\_ft}) avec séparation train/validation et sélection du meilleur checkpoint.
La génération est contrainte pour réduire les répétitions (\texttt{repetition\_penalty}, \texttt{no\_repeat\_ngram\_size}, nettoyage post-génération).

\subsection{RAFT (pseudo-RAG au train)}
\label{sec:raft}
% Notebook 05_raft.ipynb : pour chaque exemple de train, top-k FAISS + distracteurs, gabarit Instruction/Context/Input/Response ; lora_adapter_raft ; raft_predictions.json.
Le notebook~\texttt{05\_raft.ipynb} construit des exemples d'entraînement avec contexte (or ou récupéré) et distracteurs, entraîne un adaptateur dédié (\texttt{lora\_adapter\_raft}), puis infère sur le jeu de test vers \texttt{raft\_predictions.json}.

\subsection{RAG avec reranking}
\label{sec:rerank}
% Notebook 06_rag_rerank.ipynb : récupération large, cross-encoder ms-marco multilingue, top-k, Groq ; rerank_predictions.json.
Après une récupération dense élargie (top-$M$), un cross-encoder multilingue rerank les passages ; seuls les top-$k$ sont injectés dans le prompt Groq (\texttt{06\_rag\_rerank.ipynb} $\rightarrow$ \texttt{rerank\_predictions.json}).

\subsection{Function calling}
\label{sec:fc}
% Notebook 07_function_calling.ipynb : schéma outil search_docs, exécution FAISS côté client, réponse finale Groq ; function_calling_predictions.json.
Le modèle Groq peut invoquer l'outil \texttt{search\_docs} ; le client exécute la recherche FAISS et renvoie les passages avant la réponse finale (\texttt{07\_function\_calling.ipynb}).

\subsection{Alignement des gabarits prompt (perspective)}
\label{sec:prompt-align}
Pour les méthodes locales (LoRA, RAFT), tout écart entre le format d'entraînement et celui de l'inférence peut dégrader les scores ; une piste consiste à injecter systématiquement un bloc \texttt{\#\#\# Context} aligné sur l'inférence.

\subsection{Métriques}
\label{sec:metrics}
% EM, F1, BERTScore, ROUGE-L, METEOR (NLTK), IC bootstrap 95\,\% sur moyennes par paire, proxy hallucination, Acc@seuils, confiance.
Le notebook~\texttt{08\_evaluation.ipynb} calcule notamment METEOR (NLTK) et des intervalles de confiance bootstrap ($B=1000$, percentiles 2{,}5 / 97{,}5) sur les scores \emph{par exemple} pour BERTScore, METEOR, F1 et ROUGE-L (champs \texttt{bertscore\_ci95\_*}, \texttt{meteor\_ci95\_*}, etc.\ dans \texttt{final\_report.json}).
Un proxy de confiance (probabilités token-level) peut être reporté pour les générations locales (fine-tuné, RAFT) lorsque le champ est présent dans les JSON.
